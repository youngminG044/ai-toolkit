## 8. 실제 검증 결과

무엇을 왜 검사했는지 사용자가 읽을 수 있게 작성합니다. 테스트 개수·명령 성공만으로 보고를 마치지 않습니다.

- 현재 검증 기준: 코드/변경 상태·입력/설정·실행 환경·시각:
- 출력에서 확인한 실행/통과/실패/건너뜀 수 또는 집계 미확인:
- 검사 유형: 함수 계산 / 여러 모듈·HTTP 연결 / 실제 UI·수동 확인 / 빌드·정적 검사:

| 테스트·연결 기능/규칙·목적 | 입력·준비 조건 | 기대 결과·근거 | 실제 결과·판정 | 확인한 범위·한계/다음 조치 | 테스트 파일:케이스·명령/근거 위치 |
| --- | --- | --- | --- | --- | --- |

자동/HTTP 검사와 사용자의 직접 UI 확인을 구분합니다. 실행하지 않은 것은 NOT_RUN 또는 확인 대기입니다.
입력 오류를 예상대로 거절했다면 테스트는 통과할 수 있습니다. 반면 예상 밖 오류·시간 초과로 검사가 멈추면 정확성을 확인하지 못한 상태입니다.
현재 업무 테스트의 목적별 목록과 실제 케이스를 연결합니다. 사례가 많으면 요약 표와 같은 문서의 상세 목록으로 나누고 중복 실행은 합산하지 않습니다.

### 생성과 독립 규칙 검사의 관계

원본 입력/설정·최종 출력·검사 함수·공유 로직 범위와 수동 기대값을 연결합니다. 잘못된 결과를 잡는 반례와 외부 데이터 가정/미확인을 설명합니다.
