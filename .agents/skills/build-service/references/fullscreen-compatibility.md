# 전체화면을 유지해야 하는 실행 환경

현재 키트의 기본 UI는 페이지 안에서 동작하도록 구현한다. 전체화면 유지가 요구되는 환경에서는 이를 기능 수용 조건으로 다루고, 구현·오류 수정·내보내기까지 같은 기준으로 확인한다. 감시·기록·브라우저 보안을 변경하는 방식으로 해결하지 않는다.

## 기본 구현 경계

- 전체화면 진입/해제 API를 앱이 호출하지 않는다. 자식 화면만 보고 상위 IDE의 전체화면 상태를 추정하거나 앱이 다시 전체화면으로 진입시키지 않는다.
- 새 창/새 탭, 최상위 페이지 이동·새로고침, 인쇄, 네이티브 alert/confirm/prompt, 파일 선택·저장 대화상자, 다운로드·외부 앱 호출을 기본 사용자 흐름에 넣지 않는다. 환경에 따라 영향이 다르므로 모두 해제된다고 단정하지 않지만 확인 전 안전하다고도 간주하지 않는다. 필수 요구와 충돌하면 구현 전에 사용자에게 알리고 환경에서 허용한 방식을 확인한다.
- 화면 전환·도움말·JSON 미리보기는 페이지 내부 컴포넌트/패널로 만든다. 닫기 버튼은 로컬 표시 상태만 바꾸고 `type="button"`을 지정한다. 내보내기는 읽을 수 있는 텍스트 표시를 기본으로 하며 자동 다운로드·클립보드 권한 요청을 하지 않는다. 복사가 필수면 허용 조건·실패 처리를 먼저 확인한다.
- 기존 제공 프로그램과 플랫폼 지침을 보존한다. 운영체제/브라우저 단축키를 가로채 사용자를 가두거나, 전체화면 이벤트·감독 로그를 숨기거나, 감시 코드를 고치지 않는다. 사용자가 환경에서 허용한 방법으로 나갈 권리를 막는 기능을 구현하지 않는다.

## 점검과 근거

1. 앱 소스·컴포넌트·의존 UI에서 `exitFullscreen`/`requestFullscreen`과 접두사 변형, `window.open`, `target`, `location`, `print`, 네이티브 대화상자·파일/다운로드·클립보드·키보드 이벤트를 찾아 실제 호출 경로를 검토한다. 문자열 검색만으로 무위험을 보증하지 않는다.
2. 모든 버튼·메뉴·오류·닫기·출력 흐름을 목록화한다. 양식 버튼의 의도치 않은 제출·페이지 이동도 확인한다. ‘구현 후 한 번’이 아니라 영향받는 UI 수정 후 이 경로를 다시 검토한다.
3. 실제 환경 확인이 허용된 준비 공간에서만 사용자가 정상 흐름을 확인한다. 기록/제한 환경에서 해제를 일부러 재현하거나 허용되지 않은 브라우저 자동화를 쓰지 않는다. 준비 공간이 없으면 정적 점검 결과와 HUMAN_CHECK/NOT_RUN을 남긴다.
4. SERVICE.md에 점검한 코드/버전·동작·환경·관측 결과·미확인 범위를 적는다. 빌드/단위 검사 통과를 실제 IDE 전체화면 유지 검증으로 바꾸지 않는다.

앱이 해제를 유발하는 경로를 피하는 것이 구현 목표다. 브라우저·OS·사용자 동작까지 앱이 통제해 ‘절대 해제되지 않음’을 보장할 수는 없다. 탐색·탭/앱 전환 등으로 브라우저가 전체화면을 끝낼 수 있다는 [MDN 설명](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API/Guide)을 참고한다. 플랫폼의 동작/규칙과 현재 제공 버전을 우선한다.
