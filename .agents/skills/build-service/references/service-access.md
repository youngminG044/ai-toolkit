# 웹서비스의 상태·API 안내

서버/API가 있는 업무를 구현하거나 인계할 때 적용한다. 기존 스택·접속 경로·인증·운영 정책을 먼저 확인한다. 정적 화면/프런트 전용 업무는 API 해당 없음과 화면 접속 정보만 기록하며 백엔드를 추가하지 않는다.

## 상태 URL

- 기존 상태 경로를 재사용한다. 신규 서버의 기본은 GET /health이며 최소 응답은 {"status":"ok"}다. 기존 클라이언트용 별칭은 보존한다.
- 프로세스 응답(liveness)과 DB·모델 등 의존성 준비(readiness), 업무 규칙 충족 검증을 구분한다. 단순 200 응답을 전체 정상으로 설명하지 않는다.
- 상태 응답에 비밀·원시 데이터·내부 파일 경로·상세 예외를 넣지 않는다. 별도 준비 검사가 실제로 필요한 경우만 구현하고 실패 시 적절한 비성공 코드를 반환한다.

## API 안내 URL과 내용

- 현재 라우트 계약에서 메서드·경로·목적·요청/응답·주요 오류를 확인할 수 있게 한다. API를 바꾸면 계약과 예시도 갱신한다.
- FastAPI 뼈대는 /api에 외부 리소스 없는 목록, /docs·/redoc에 문서 UI, /openapi.json에 계약을 제공한다. 다른 스택은 기존 문서 도구나 간단한 읽기 전용 안내로 같은 목적을 충족한다.
- 예시는 합성 입력을 사용한다. 문서 UI에서 쓰기 요청을 실행하면 데이터가 바뀐다는 점을 구분하고 확인에 필요한 최소 사례만 실행한다.
- 기존 비공개 정책·권한을 유지한다. 개발 문서가 필요하다는 이유로 운영 API나 문서를 익명 공개하지 않는다. FastAPI 뼈대는 ENABLE_API_DOCS=false로 목록·문서 UI·스키마를 함께 끌 수 있다. 이 설정은 업무 API의 인증/권한을 대신하지 않는다.
- 주소 안내를 위해 제품 화면에 새 탭/페이지 이동 버튼을 추가하지 않는다. 전체화면 유지가 요구되면 [환경 호환 기준](fullscreen-compatibility.md)을 따르고, HTTP 확인과 허용된 준비 환경의 UI 확인을 구분한다. 개발 문서 링크가 환경의 탐색 제한을 바꾸지 않는다.

## 업무 폴더의 SERVICE.md

업무 설명이 있는 README.md/readme.md를 보존하고 별도 SERVICE.md에 아래 정보를 유지한다. [서비스 기술 설명서 기준](service-document.md)에 따라 구조·명세·규칙·근거·검증·효과와 함께 설명한다. 기존 SERVICE.md는 보존·보완하며 별도 필수 RUN.md가 있으면 상세 절차를 연결한다. 추가 파일이 금지되면 허용된 문서·위치를 확인하고 안내한다.

- 실행 명령과 서버 유지 방법, 실제 바인딩·포트, 입력/저장 위치.
- 화면, /health 또는 기존 상태 경로, API 목록, 문서 UI, 스키마의 실제 접속 정보. 해당 없음·비공개는 그 이유.
- 로컬은 실제 localhost URL을, 웹 IDE는 내장 Browser에서 선택할 포트·경로를 적는다. 확인하지 않은 외부 접속 주소를 만들거나 터널을 열지 않는다.
- 대표 정상·잘못된 입력의 HTTP 확인 명령, 기대 결과·실제 결과·미검증. 실행하지 않은 예시는 실행 예시로만 표시한다.
- 문서 공개 설정, 현재 인증/권한 범위, /health가 검사하는 범위와 검사하지 않는 범위.

실제로 서버를 실행하고 상태·문서/스키마·대표 업무 경로를 HTTP로 확인한다. 프런트 프록시를 쓴다면 프록시를 통한 경로도 확인하고, 오류가 나면 실제 포트·라우트·서버 로그부터 좁힌다. 문서 페이지 200, 업무 검증, 사용자의 수동 UI 확인을 구분한다. devlog.md와 probe.md에는 실제 변경·검증·선택 이유를 반영한다.
