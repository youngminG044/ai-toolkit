# MCP·플러그인이 필요한지 판단

현재 파일·터미널·HTTP/SDK·연결된 도구로 충분하면 그대로 진행한다. 로컬 CSV 처리, 앱 구현, 테스트, 상태 URL/API 문서에는 MCP가 필수가 아니다. 개발 중 Codex에 도구를 연결하는 것과 완성 앱이 실행 중 API/모델을 호출하는 것은 별도 설계다.

새 연결을 검토할 상황은 제공된 외부 시스템의 자료 조회·공식 문서 검색·기존 작업 도구의 기능이 필요하고 현재 수단이 이를 제공하지 못할 때다. 공개 지침만 필요한 Skill과, 도구를 노출하는 MCP, 이들을 묶을 수 있는 플러그인을 구분한다.

- 먼저 이미 연결된 도구와 제공 환경의 설정 화면을 확인한다. 플러그인 도구가 충분하면 재설치하지 않는다.
- 후보를 정할 때 공식 배포처·필요 기능·접근할 데이터·외부 전송·인증/비용·현재 제공 버전 호환·설정 소요를 확인한다. 개인 자격 증명이나 외부 계정 권한이 필요하면 그것을 이미 받은 것으로 간주하지 않는다.
- 설치할 연결이 확정되지 않았다면 후보와 이유·대안·시간 영향을 사용자에게 제시한다. 이미 해당 연결과 권한이 승인돼 있으면 같은 확인을 반복하지 않는다.
- 현재 업무 환경의 MCP/Plugin 설정 수단과 허용 범위를 따른다. 관리 설정의 쓰기 제한을 우회하거나 도구를 위해 버전·인증·전역 설정을 임의로 바꾸지 않는다. 연결할 시스템과 전송할 데이터가 업무 권한 범위 안인지 확인한다.
- 설정 뒤 등록 상태, 인증, 실제 사용할 도구의 존재와 최소 읽기 호출을 확인한다. 공개 문서 연결은 일반 기술 키워드로 확인하고, 업무 자료가 필요한 연결은 허용된 최소 범위로 검증한다. 비밀 값은 요청/로그/문서에 노출하지 않는다. 설정 저장만으로 연결 성공이라고 쓰지 않는다.
- 사용할 수 없으면 로컬 파일·허용된 공식 문서·직접 HTTP/SDK 등 가능한 대안으로 진행하고 불가능한 부분과 시간 영향을 알린다. 새 연결을 권한 없는 외부 전송·계정 접근의 우회 수단으로 사용하지 않는다.

사용한 연결·출처/버전·권한 범위·실제 호출 목적·확인 결과·남은 한계를 실제 업무의 devlog.md와 probe.md에 필요한 만큼 기록한다. 인증 값이나 원시 민감 데이터를 옮기지 않는다.
