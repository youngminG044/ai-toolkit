# 업무 유형에 맞는 기준만 선택

| 유형 | 먼저 확정 | 최소 작동 경로 | 실패하기 쉬운 지점 |
| --- | --- | --- | --- |
| 업무 서비스 | 사용자·업무 결정·상태 전이·필수 화면 | 대표 입력 하나가 실제 규칙을 거쳐 결과/저장까지 도달 | 가짜 버튼, 새로고침 시 유실, 잘못된 집계 |
| 데이터 분석·ML | 행의 의미·의사결정 시점·정답/목표·운영 지표 | 데이터 점검→단순 기준선→실제 평가→해석 | 누수, 잘못된 분모·단위, 테스트 데이터로 튜닝 |
| 알고리즘·최적화 | 입력 크기·제약·최적화 목표·동점/불능 처리 | 작은 입력의 단순 해법과 비교 가능한 구현 | 경계값, 시간복잡도, 실행 불가 해를 정상으로 반환 |
| 문서·업무 개선 | 독자·결정·필수 근거·출력 형식 | 근거 표→핵심 결론→실행안→검증 | 없는 사실, 인과 과장, 실행 주체·조건 누락 |
| 파일 변환·자동화 | 입력/출력 계약·보존 항목·반복 실행 정책 | 실제 파일 1개 처리→읽어 재검증 | 문자 인코딩·형식 손실, 중복 적용, 조용한 덮어쓰기 |
| 검색·LLM 기능 | 허용 모델/API·근거·출력 스키마·지연/비용 | 고정된 합성 사례로 입력→근거→검증된 출력 | 외부 전송, 환각, 프롬프트 입력을 명령으로 신뢰 |

혼합 업무에서는 핵심 사용자 가치의 경로를 하나 먼저 완성한다. 고정된 앱 템플릿에 문제를 맞추지 않는다. 실제 업무의 API 사용 허용이 확인되지 않으면 LLM 연결을 가정하지 않는다.

담당자 질문 예: 누가 이 결과를 보고 무엇을 결정하는가? 어떤 오류가 더 비싼가? 값이 기준과 같을 때는 어떻게 처리하는가? 결측은 미측정인가 0인가? 결과에 반드시 포함할 근거와 인계 형식은 무엇인가?
