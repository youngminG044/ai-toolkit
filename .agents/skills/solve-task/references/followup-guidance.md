# 별도 후속 문항이 있는 경우의 참고

현재 절차에서 후속 문항이 명시되었거나 사용자가 서술형 대비를 요청한 경우 읽는다. 대비 요청만 있는 업무에서는 아래의 문항 수·시간·제한을 시험 규정으로 가정하지 않는다. 담당자와 협업하는 일반 업무 관점과 180분 집중 세션의 60/60/60 운영안은 그대로 유지한다. 후속 절차가 있다는 이유로 평소 업무를 문항 답변이나 점수 중심으로 바꾸지 않는다.

## 보존할 조건

- 안내된 구성은 6문항, 문항별 5분, 총 30분이다. 실제 문항 수·시간·진행 규칙이 다르면 최신 안내를 따른다.
- 180분 구현/보완/이해 세션과 후속 30분을 구분한다. 후속 시간이 별도인지 같은 전체 마감에 포함되는지 확인하고, 불명확하면 미확인으로 표시한다. 마지막 코드 이해 60분을 임의로 줄여 후속 시간을 배정하지 않는다.
- 제출/확정 시점, 이후 파일 변경 가능 여부, 문항 간 이동·수정 가능 여부, 자료 열람 범위는 실제 안내에 맞춘다. 과거의 특정 시각을 현재 마감으로 재사용하지 않는다.
- AI·복사/붙여넣기가 금지된 후속 구간에서는 에이전트의 답안 작성·수정·검토 도움을 중단한다. 이전 단계에 작성한 문서가 후속 단계의 열람/도구 사용 허용을 뜻하지 않는다.
- 해당 구간의 금지 범위에 자동 감시·파일 변경이 포함되면 진입 전에 저장 상태와 최종 스냅샷, 감시 종료를 확인한다. 이미 중단했는지 실제 상태로 확인한다.

## 사전 이해와 실제 근거

도움이 허용된 180분 세션에서 본인의 코드 흐름·업무 규칙·기술 대안·실제 AI 제안 검토·검증·한계를 이해한다. 첫 60분은 구현, 다음 60분은 보완과 이해, 마지막 60분은 변경 없는 이해에 사용한다. SERVICE.md·probe.md·devlog.md는 실제 근거를 찾는 자료이며 수행하지 않은 작업을 만들어 채우지 않는다.

## 예상 질문·예시 답변을 자동 준비

후속 서술형 안내 또는 사용자의 대비 요청이 있으면 별도 스킬 호출을 요구하지 않고 구현·검증 뒤 준비한다. `explain-work`가 있으면 그 스킬의 `references/written-preparation.md`를 읽는다. 선택 설치로 없더라도 다음 기본 형식을 적용한다.

- 현재 코드·테스트/실행 결과와 존재하는 SERVICE.md·probe.md·devlog.md를 대조한다. 문서나 이력이 없으면 있는 근거만 사용하고 누락은 미확인으로 둔다.
- 기본 6개 주제인 요구사항·핵심 동작, 기술 선택·대안, 코드 흐름·예외, 검증·오류 해결, AI 활용·본인 판단, 한계·개선에서 보통 한 문제씩 만든다. 사용자가 지정한 문항 수·분량을 우선하며 실제 출제 문항이나 공식 정답으로 소개하지 않는다.
- 질문마다 핵심 요점 한 문장, 3~5문장 예시 답변, 실제 파일·함수·해당 테스트/결과·기록 근거, 확인 상태를 채팅에 제공한다. 예시 답변은 AI가 작성한 사전 학습용 초안으로 표시한다. 업무 probe.md의 `서술형 대비` 구획에 정리하며 추가 문서 제한이 있으면 허용된 위치나 채팅을 사용한다. 새 답안 파일은 기본 생성하지 않는다.
- AI가 실행한 작업과 사용자가 직접 판단·검증한 범위를 구분한다. 수행하지 않은 수정·실험·사용자 채택/기각·수치를 만들지 않는다. 판단 기록이 없으면 사용자 판단 확인 전이라고 밝힌다.
- 기본 세션의 T+120분 전까지 준비하고 관련 코드/검증 변경 시 영향받는 답변만 갱신한다. 마지막 60분에는 준비된 질문으로 한 문제씩 사용자 답변을 기다리고 실제 근거와 대조한다. 이때 처음 요청받아 자료가 없으면 새 문서 묶음 대신 현재 코드에 대한 한 문제와 짧은 설명부터 진행한다. 사용자 미응답은 답변 대기로 둔다.

실제 AI 금지 후속 구간 진입 시 위 준비·연습도 중단한다. 사전 자료의 열람·복사 가능 여부는 실제 안내를 따른다. 실제 제한이 없는 업무에서는 담당자 질문과 설명·검토를 합의한 범위에서 계속한다. 이 참고 문서만으로 도구 사용 제한이나 제출 후 변경 금지를 새로 만들지 않는다.
