# 실제 구현에 근거한 서술형 대비

후속 서술형이 안내되었거나 사용자가 대비를 요청했을 때 사용한다. 구현·검증 후 예상 질문과 예시 답변을 준비하고 코드 이해 시간의 직접 답변 연습으로 연결한다. 실제 출제 문항이나 공식 정답으로 소개하지 않는다.

## 먼저 읽을 근거

현재 요구사항과 실제 코드·테스트/실행 결과를 읽고, 업무 probe.md의 기능·선택 이유/대안, devlog.md의 실제 AI 제안·사용자 판단·실패/수정 이력을 대조한다. 서비스라면 SERVICE.md의 흐름·계약도 확인한다. 특정 문서가 없으면 존재하는 자료를 사용하고 빠진 사실을 미확인으로 둔다. 이 준비를 위해 미작성 기록을 과거에 있었던 일처럼 채우지 않는다.

## 기본 6개 주제

주제별로 현재 구현의 중요한 사례를 골라 보통 한 문제씩 만든다. 사용자가 문항 수·분량을 지정하면 그 조건을 우선한다. 아래 질문은 구성 예시이며 실제 기능·선택·사건을 넣어 구체화한다.

| 주제 | 예상 질문의 방향 | 확인할 근거 |
| --- | --- | --- |
| 요구사항·핵심 동작 | 어떤 업무 문제를 해결하며 필수 요구를 어떤 동작으로 구현했는가? | 요구사항, 담당자 답변, 실제 기능 |
| 기술 선택·대안 | 이 방식을 선택한 이유와 대안 대비 감수한 한계는 무엇인가? | 구현/의존성, 결정 기록, 비교한 대안 |
| 코드 흐름·예외 | 대표 입력이 어디서 검증·처리·저장되고 예외는 어떻게 처리되는가? | 진입점→함수→출력, 분기/오류 처리 |
| 검증·오류 해결 | 무엇을 어떻게 검증했고 실패나 미검증은 어떻게 다뤘는가? | 테스트 케이스, 기대/실제 결과, 수정 이력 |
| AI 활용·본인 판단 | AI에 무엇을 맡겼고 어떤 제안을 어떤 근거로 검토·유지·수정했는가? | 실제 대화/이력, 사용자 판단과 재확인 |
| 한계·개선 | 현재 남은 한계와 조건 변화 시 우선 개선·재검증할 것은 무엇인가? | 미구현/미검증, 운영 제약, 다음 확인 방법 |

## 질문마다 제공할 내용

- **예상 질문:** 현재 기능이나 사건을 특정한 문장.
- **핵심 요점:** 먼저 말할 결론 한 문장.
- **예시 답변:** 보통 3~5문장으로 결론→이유/처리 방식→구체적 검증 근거→한계 중 해당 내용을 연결한다. 실제로 설명할 수 있는 용어와 작은 사례를 사용한다.
- **근거:** 확인한 파일 경로·함수, 해당하면 테스트 파일/케이스·명령·실제 결과와 기록 구획. 테스트 코드의 존재와 실행 결과를 구분한다.
- **확인 상태:** 구현/검증 사실과 사용자 직접 확인 여부, 남은 미확인 사항.

채팅에 질문과 답변을 실제로 보여주고 업무 probe.md의 `서술형 대비` 구획에 정리한다. 기존 기능·결정·테스트 상세는 위치를 연결하고 반복 복제하지 않는다. 추가 문서가 금지되면 허용된 문서 구획이나 채팅에 제공한다. 실제 업무 내용은 공개 배포 키트에 저장하지 않는다.

예시 답변은 **AI가 작성한 사전 학습용 초안**으로 표시한다. AI가 실행한 검사를 사용자가 직접 실행했다고 쓰거나, 기록에 없는 사용자 채택/기각·담당자 동의·성능 수치·버그 수정 경험을 만들지 않는다. 실패 이력이 없다면 실제 정상/경계 검증과 미검증을 설명한다. 판단 기록이 없으면 사용자 판단 확인 전이라고 밝히고 사용자가 근거를 설명할 질문으로 남긴다.

## 준비 시점과 갱신

기본 180분 세션의 T+60~120분에 구현·검증과 병행해 준비한다. T+120분 전에 코드나 검증 결과가 바뀌면 영향받는 답변·근거만 갱신한다. 관련 기능이 미완성이면 그 상태와 미검증을 명시한다. 질문·답변 생성이 기능 완료나 사용자 이해 완료를 뜻하지 않는다.

T+120~180분에는 준비된 자료와 현재 코드로 연습한다. 이때 처음 대비를 요청받아 자료가 없다면 현재 근거로 질문 하나와 짧은 설명부터 진행하고, 미작성 자료 상태를 알린다. 새 문서 묶음이나 기록 보완으로 마지막 이해 시간을 사용하지 않는다. 사용자가 다른 일정을 명시하면 그 일정과 이해 시간 영향을 반영한다.

## 직접 답변 연습과 실제 후속 단계

준비 자료를 제공한 뒤 한 문제씩 질문하고 사용자 답변을 기다린다. 연습에서는 예시 답변을 먼저 반복하지 않고 사용자가 자기 말로 설명하도록 한다. 답변을 코드·실제 결과와 대조해 맞는 근거, 다른 부분, 빠진 한계를 짚고 필요한 부분만 다시 설명한다. 사용자 미응답은 `답변 대기`로 두며 에이전트가 대신 답한 것을 사용자 이해로 기록하지 않는다. 연습 여부·확인 범위는 probe.md에 짧게, 실제 생성/갱신·연습 사건은 devlog.md에 남긴다.

질문·예시 답변 준비와 연습은 AI 도움을 허용한 단계에서만 수행한다. AI 사용이 금지된 실제 후속 서술형 단계에서는 질문·답변 생성, 답안 작성·수정·검토를 중단한다. 사전에 준비한 자료가 실제 단계의 열람·복사/붙여넣기 허용을 뜻하지 않는다. 실제 문항 수·시간·도구/자료 조건은 현재 안내를 따르며 대비용 6개 주제로 시험 구성을 추정하지 않는다.
